# 本地运行与接口使用

当前实现提供终端、登录页、五个工作页面和 HTTP 后端。用户素材、模板、历史和生成文件持久保存在 `data/`，关闭程序不会删除它们。首次使用会创建空白素材库，不会自动使用仓库里的示例或个人经历。

## 模板库

网页「模板库」提供系统模板和「我的模板」。先预览，点击「使用此模板」，工作台会显示当前选择；后续任务提交时固定此选择，任务开始时复制源文件供模型读取。选择只影响后续任务，已有简历保持不变。

上传 PDF、PNG、JPG 或 WebP（单文件不超过 15 MB；PDF 不超过 10 页），填写名称并点击「上传并转换」。后端读取页面图片和文字，调用配置的视觉模型重建 LaTeX，最多进行三次转换/编译修复，编译两遍并确认预览为一页，再让模型查看截图检查重叠、裁切与对齐，通过后保存到个人模板库。转换失败可以重试，未完成的模板不能选择。可下载 LaTeX、示例 PDF 和原稿。PDF 通常无法还原原始 LaTeX，转换是对版式的重建，复杂布局可能有差异，使用前应检查预览。

首次生成完整 LaTeX，后续编译或截图检查发现问题时，只请求局部代码替换；后端核对源码版本、唯一匹配和编辑区域，全部有效才应用。匹配失败不会部分改写文件，也不会退回整份重写，而是将原因返回模型重新定位。修改后仍重新编译、检查页数与截图。页面会显示「正在局部修复模板代码」，任务日志记录应用/拒绝结果及修改数量。已有模板后续直接复用，不重复转换原稿。

模板转换独立于个人简历导入：不读取或改写个人素材、不将模板示例保存为简历版本；模型被要求替换参考人物的信息，示例内容不能作为生成简历的事实依据。个人模板和原稿均需当前用户凭据访问。

扩充系统模板时，在根目录 `模板/` 放入独立可编译的 `.tex` 文件，以及同名 `.pdf` 供预览；可选同名 `.json` 配置展示名称和简介，例如 `{"name":"简洁双栏","description":"适合突出项目成果的双栏版式"}`。模板应支持缺图编译，使用 `geometry` 和 `graphicx`，为 `photo.jpg` 留出照片位置。列表动态发现，无需修改前端；只有 `.tex` 时仍可选择，但没有预览。新增模板后同步维护 `AGENTS.md` 的目录清单。

## 安装与配置

使用 Python 3.10 或更高版本。建议创建独立虚拟环境：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

如果系统缺少 venv 支持，可以安装系统的 `python3-venv`，或者用已安装的 uv：

```bash
uv venv --python python3 .venv
uv pip install --python .venv/bin/python -r requirements.txt
```

参考 `.env.example` 在 `.env` 中配置 `AGENT_API_KEY`、`AGENT_MODEL`，以及需要时的 `AGENT_BASE_URL`。已有 `.env` 不要覆盖。使用 `RESUME_DATA_DIR` 可指定持久数据目录。

`AGENT_REASONING_EFFORT=medium` 会在每次模型请求中显式传入 `reasoning_effort="medium"`。不支持该参数的模型应将此项留空。修改 `.env` 后重启终端或后端进程生效；同名的进程环境变量优先于 `.env`。

每次模型请求直接使用完整素材。聊天及简历生成的每次模型请求都直接携带当前用户最新的完整 `项目经历库.md`，使用 `tools.py` 直接提供文件读写、编译和预览工具。无需修改 `.env`。生成时优先覆盖已确认的经历和关键成果，确实超过一页再压缩；完整输入不等于取消一页限制，也不会使待确认事项自动成为已确认事实。

PDF 编译还需要 xelatex、fandol 中文字体、fontawesome5 与 tex-gyre。截图预览需要 `pdftoppm`（Ubuntu/Debian 的 `poppler-utils` 包）。模型和中转接口必须支持 Chat Completions 的图片输入。API 可以在未配置模型时启动，但发送消息会得到明确的配置错误。

## 简历的局部迭代

生成简历时，模型先用 `write_file` 写出第一版 LaTeX；后续默认在同一文件上用 `edit_file` 局部修改正文、加粗或排版代码；调整较大时，也允许用 `write_file` 写回修改后的完整源码，由模型自行选择。模型通过 `read_file` 获取当前内容及版本，按原代码/新代码提出局部替换。修改失败保留当前文件，成功后重新编译和检查截图；行距、下边距继续使用 `compile_pdf` 参数调整。新任务仍保存独立简历版本，已生成的历史版本不被覆盖。

## 终端

```bash
.venv/bin/python agent.py
.venv/bin/python agent.py --new-session
.venv/bin/python agent.py --session 已有会话编号
```

默认恢复同一终端用户的最近会话；新会话仍共享该用户的素材库。启动时显示素材库路径，可以通过对话补充真实经历，也可以在没有任务运行时编辑该 Markdown。已有素材可人工复制到该用户的 `项目经历库.md`，不要把示例人物混入个人素材。

输入 `exit` 或 `quit` 退出。终端凭据保存在数据目录的 `cli-profile.json`，不要分享或提交到版本库。

## 启动后端

```bash
.venv/bin/python -m uvicorn api:app --host 127.0.0.1 --port 8000
```

浏览器访问 <http://127.0.0.1:8000> 即可使用网页。若要继续使用原型时的地址，把端口改为 `8765` 并访问 <http://127.0.0.1:8765>。不要再用 `python -m http.server`，静态文件服务无法调用模型。

当前要求单进程运行，不使用多个 workers。终端和 API 不能同时占用同一个数据目录；需要分别运行时，先退出另一个入口，或指定不同的数据目录。

## 网页上传与自动入库

网页首次打开进入登录页，任何人都可注册普通账号。登录后访问自己的素材、模板、照片和简历。旧浏览器存在原工作空间凭据时，注册页默认勾选绑定原资料，沿用原用户编号和数据。模型密钥只由后端读取 `.env`，不会下发浏览器。

1. 在对话框选择 PDF、DOCX、PNG/JPEG/WebP 图片或 TXT/MD，也支持粘贴和拖入图片；输入说明后一起点击发送。前端只上传原文件，不提取文字。
2. 服务器保存原文件并提取 PDF/Word 内容；PDF 全部页面、用户图片和 Word 可转换的内嵌图片作为图片输入传给模型，扫描 PDF 同样可读。文字说明和附件进入同一轮 Agent 对话。
3. 模型识别为用户本人简历时主动整理已确认信息入库；JD、参考图与他人简历不当作用户经历。用户可明确要求只查看不保存。
4. 素材库自动读取后端结果，保留手工编辑、revision 冲突检查和用户任务锁。解析失败、模型失败可重试，刷新可恢复任务与已发送附件。
5. 原文件保存于 `data/users/<用户>/workspace/uploads/<编号>/`，经身份与会话校验才能下载。历史保存附件编号，图片只在服务器构造模型请求时编码。

每条消息最多 3 份文件，每份 15 MB；单 PDF 最多 10 页，单文件文本 6 万字符，一条消息合计不超过 12 万字符或 12 张图片/页面。旧 `.doc` 请转 DOCX；有密码的 PDF 先解密。后端需 `python-multipart`、`python-docx`、Pillow、pypdf 和 pdftoppm；Python 依赖通过 requirements.txt 安装。

旧 `/imports` 文本接口保留以兼容历史任务，但网页已不再调用。

2026-10-04 上传迁移验证：29 项自动测试通过。真实中转模型能同时读取图片中的测试编号和 DOCX 中的项目数据，并遵守“只查看不写素材”的要求；另一次真实调用完成 DOCX 个人信息与项目经历入库。浏览器验证了原文件与文字同条发送、附件历史刷新恢复和原图预览。原始附件通过字节对比确认完整保存，跨用户/会话访问被拒绝，失败任务可用原附件重试。

## 账号与手机号登录

用户名为 3～32 位，以英文字母开头，支持数字、点、下划线和短横线；密码为 6～128 个字符。注册账号默认都是普通用户，不会因为最先注册获得管理员权限。账号页支持修改密码、绑定手机号和退出登录；管理员可查看用户、停用/恢复账号、重置密码。修改或重置密码、停用账号都会撤销旧登录会话。

先在网页注册自己的账号，再在服务器终端授权管理员：

```bash
.venv/bin/python account_admin.py promote 你的用户名
```

使用自定义数据目录时增加 `--data-dir /你的持久数据目录`。忘记密码且尚未绑定可用手机号时，服务器管理员可运行以下命令，按提示输入新密码（不在命令参数中传密码）：

```bash
.venv/bin/python account_admin.py reset-password 你的用户名
```

手机号第一版支持中国大陆 +86：短信验证注册、验证码登录、绑定手机号、验证码重设密码。用户名账号需先验证并绑定本人手机号，才能用手机号找回同一账号；直接注册另一个手机号账号不会自动关联旧资料。当前不提供直接更换已绑定号码的界面。

真实短信需要网站运营方开通服务，普通用户不需要开通。当前适配阿里云短信，默认关闭；未配置时网页明确提示不可用，后端拒绝发送，不会把验证码回显到页面、API 响应或日志。测试中的模拟短信仅在隔离测试环境注入。

1. 在服务商申请短信签名和验证码模板，模板变量使用 `code`。参见[阿里云短信 Python 接入说明](https://help.aliyun.com/zh/sms/developer-reference/using-python-openapi-example)。
2. 安装可选依赖：`.venv/bin/python -m pip install -r requirements-sms.txt`。
3. 在服务器 `.env` 填写 `RESUME_SMS_PROVIDER=aliyun`、`ALIBABA_CLOUD_ACCESS_KEY_ID`、`ALIBABA_CLOUD_ACCESS_KEY_SECRET`、`RESUME_SMS_SIGN_NAME` 和 `RESUME_SMS_TEMPLATE_CODE`；不要把密钥发到聊天或提交 Git。
4. 重启后端后，`GET /auth/config` 的 `sms_enabled` 表示配置和依赖已齐全；实际能否发送仍以短信服务商结果为准。

验证码 5 分钟有效、使用一次即失效，按注册/登录/找回/绑定分别验证，最多允许 5 次错误尝试。同一手机号所有用途共用每分钟 1 次、每小时 5 次的发送上限；全站默认每小时 100 次，可通过 `RESUME_SMS_HOURLY_LIMIT` 调整。登录、注册和敏感操作也有数据库持久化限流。

登录态使用 7 天有效的 HttpOnly / SameSite=Lax Cookie；数据库只保存登录凭据摘要，密码使用 Argon2id 哈希。公开部署使用 HTTPS，并设置 `RESUME_PUBLIC_ORIGIN=https://你的域名`、`RESUME_COOKIE_SECURE=true`。浏览器本地仅保留用户编号、会话位置和按用户隔离的未保存草稿；旧凭据只用于一次性绑定，绑定成功后服务端作废旧凭据。不要在绑定旧资料前清除原浏览器站点数据。

## 请求示例

健康检查：`curl http://127.0.0.1:8000/health`。正常业务接口使用登录 Cookie，旧 `POST /users` 和 Bearer 凭据不再对外提供账号访问能力。只有隔离回归测试显式开启旧接口兼容。

登录后的网页控制台可运行以下示例创建会话；浏览器自动携带 HttpOnly Cookie，无需复制登录凭据：

```javascript
const auth = await fetch('/auth/me').then(r => r.json());
const session = await fetch('/sessions', {
  method: 'POST',
  headers: {
    'X-Resume-Client': 'browser',
    'X-CSRF-Token': auth.csrf,
    'X-Resume-Account': auth.account.user_id
  }
}).then(r => r.json());
console.log(session);
```

所有写请求需要 `X-Resume-Client: browser`，已登录的写请求还需 `/auth/me` 返回的 CSRF 值，跨来源写请求会被拒绝。网页额外发送 `X-Resume-Account` 防止多个标签页切换账号后误把旧草稿写入另一账号。会话创建后使用 `/sessions/{session_id}/messages` 发送/读取消息，`/sessions/{session_id}/tasks/{task_id}` 查询任务，`/sessions/{session_id}/files/{file_id}` 下载文件。

发送消息返回任务编号，不会等待模型完成。查询任务直到 `completed` 或 `failed`；`files` 列表包含文件编号与名称，按对应扩展名下载。编译失败可能只保留 .tex，不能将任务完成等同于 PDF 一定生成。

同一用户的素材被多个会话共享，因此有未完成任务时再次发送消息返回 409。换用另一个用户的凭据访问会话、任务或文件会返回 404。

## 数据迁移和备份

在「简历版本」选择一份简历，点击预览右上角「删除」并确认，可删除该版本。后端同时删除对应 PDF、同名源文件与下载记录，素材库和原始附件保留；已删除版本无法通过旧下载链接访问。

停止写入后备份整个 `data/`（或自定义数据目录），其中包括 SQLite 数据库、用户文件、`auth-secret` 验证码校验密钥以及需要继续使用的终端凭据。只备份 PDF 无法恢复会话、素材及文件归属。

服务重启可以恢复已有用户、会话和结果；中断任务会变为失败，需要重新提交。当前没有自动定时备份和云对象存储；账号找回可使用已配置的短信服务或服务器管理员重置。

这个版本用于本地开发。公开部署前还需正式登录、使用配额、备份策略和操作系统级编译隔离。

## 内容与排版检查

素材入库保留独立项目要点，生成时先完整表达，再根据实际超页情况调整。正文成果数字和单位应使用 `\textbf{...}`，不只加粗标签。`resume_review.py` 在编译后检查明确的成果加粗，以及页底明显有空白时的项目条目过度合并，失败会要求修改并重新编译，不把失败 PDF 提供下载。页底比例基于文字基线估计，不是完整的视觉判断。

每次编译后自动截图并把真实图片传给模型，让模型检查留白、拥挤、加粗和对齐，必要时修改后重编。最多 6 轮截图；交付前必须查看与当前正文及素材匹配的 PDF 截图。未通过检查的草稿保存在临时目录，仅供模型预览，不进入简历版本库。图片不写入聊天历史。截图失败或接口不支持图片输入时会报告失败，不伪称已完成视觉检查。

2026-10-04：22 项自动测试通过，覆盖草稿截图、图片传入模型请求、三轮上限、正文/素材变化使预览失效、图片请求被拒绝和未检查 PDF 不发布。使用当前中转的 `gpt-6-astra`（请求参数 `medium`）实测图片输入成功，模型识别出仅存在于测试图片中的文字与明显留白。多模态消息格式参考 [OpenAI Docs：Images and vision](https://developers.openai.com/api/docs/guides/images-vision)。

同日用真实素材和上一版简历的隔离副本完成 Agent → MCP 编译 → 自动截图 → 模型视觉检查 → 一页 PDF 的完整联调。该次模型在第一轮截图后认为版面可交付，没有触发第二轮修改；多轮修改与三轮上限由自动测试覆盖。这证明链路可用，不代表任意简历都能自动达到理想排版。

## 本地工具调用

后端已统一使用 `tools.py`，移除 `mcp_client.py`、`mcp_server.py` 和 MCP 依赖。Agent 直接获取工具定义并调用 Python 函数；模型仍能使用读、创建、局部修改、编译、预览五项能力。用户目录、输出目录和预览缓存按任务独立持有。编译与截图命令异步运行，取消或超时后回收子进程。此前 MCP 联调记录仅代表迁移前的历史验证。重启运行中的后端以加载新代码。

## 页底留白基准

生成简历统一参考 `resume-Agent开发.pdf` 的 3.62% 页底留白（A4 约 10.76 mm），程序验收上限为 4.00%（A4 约 11.88 mm）。比例按最后文字基线到纸底计算，含正常页边距，不是整页白色面积。`compile_pdf` 超限时不交付 PDF，保留临时草稿供截图检查；`layout_checks` 提供本轮测量值和目标。先补足与 JD 相关的真实内容，再调整允许的间距；素材不足时说明待补充信息，不冒充完成。本轮已编译但结束时仍无合格 PDF，任务返回失败及最后编译原因。重启后端加载新检查。

## 任务耗时与端到端监控

重启后端并刷新网页后，工作台输入框上方可展开「任务耗时」，查看当前步骤、已等待时间、每轮模型请求、工具和子进程的耗时。下拉框可切换当前会话最近 10 次任务；任务执行时每秒更新。模型请求展示接口提供的输入/输出 token 数，以及本次图片数和接下来调用的工具。编译调用结束与质量验收通过是两个不同指标，未通过会显示「验收未通过」。

`GET /sessions/{session_id}/tasks/{task_id}` 和最近任务列表均返回 `performance`，沿用原有用户鉴权；逐步事件保存在 SQLite，无需另装监控服务。子进程/质量检查是工具的子步骤，已经包含在工具总耗时中，不可重复累加。服务端总耗时从消息处理函数开始接收/保存请求算起，加上建任务后的排队与执行；浏览器另存本机「发送至受理」「发送至结果显示」「结果刷新」和最近一次 PDF 下载/渲染耗时。两种总耗时不能相加。浏览器数据在当前用户的 localStorage 中，其他设备不可见，刷新页面可恢复。

也可以在项目目录只读诊断（不调用模型、不改数据库）：

```bash
.venv/bin/python -m task_metrics --limit 10
# 指定其他数据目录：添加 --data-dir /绝对路径
```

旧任务只根据已有事件估算模型等待区间，并标注「历史估算」；无法补回 token、上传、子进程或浏览器耗时。新模型计时包含网络、中转服务、生成及 SDK 内部重试，当前使用非流式请求，不能据此拆分首字延迟、生成速度或确认重试次数。未进入消息处理函数前的代理等待不计入服务端时间；在创建任务前失败的上传没有任务时间线。浏览器总耗时包含上传、网络、约 1 秒的轮询间隔与界面刷新，跨刷新恢复时使用本机墙钟，系统时间调整可能影响它。

## 个人证件照

在「我的素材库」顶部上传本人证件照，支持 JPG、PNG、WebP，最大 5 MB。后端校验并标准化保存为当前用户工作区的 `assets/photo.jpg`，与文字素材分开管理，不把图片编码写进 Markdown。普通聊天附件和参考简历图片不会自动被认定为证件照。

每个新生成任务复制一份 `photo.jpg`，模型会收到照片是否可用的信息；已上传时，中英文简历都必须在页眉包含该照片。编译器检查 PDF 实际绘制的图片是否匹配本任务照片，遗漏时验收失败并要求重编；截图检查继续负责照片位置、比例、遮挡和整体版面。照片变化会使旧截图失效。生成目录保留照片副本，并作为任务文件随 `.tex` 提供，下载源码后需将照片放在同目录才能复编。更换或移除个人照片不会改动历史简历；执行任务期间暂不能更换或移除。

接口：`GET /profile` 查询照片状态；`GET /profile/photo` 查看照片；`PUT /profile/photo` 用 multipart 字段 `photo` 上传；`DELETE /profile/photo` 移除。所有接口沿用用户凭据，只操作当前用户照片。

后端现会比较加载时与磁盘上的 Python 代码指纹；发现代码变化后，生成、导入、重试接口返回 503 并明确要求重启。`/health` 提供 `backend_revision` 与 `restart_required`，便于检查运行版本。此检测从加载了该功能的新进程起生效，AGENTS.md 仍在每次任务开始时读取。

## 让模型依据测量主动微调

模型现在可以直接调用已有编译工具，避免只改参数却重新输出整份简历：

```json
{"tex_file":"resume.tex","layout_json":"{\"line_spread\":1.08,\"bottom_mm\":10}"}
```

只传需要改变的参数，另一项保留上次覆盖值；省略 `layout_json` 则直接编译当前源码。参数范围、测量—查看截图—选择下一组的步骤写在 `AGENTS.md` 的“模型测量与排版微调”。后端只应用模型选定的值，正文保持不变。工具返回当前与历史测量，任务监控也展示每轮参数、页数和留白。截图检查上限已由 3 轮改为 6 轮，仍受 600 秒时限约束；增加机会不保证所有简历自动成功。
