# 本地运行与接口使用

代码已按目录归类：`backend/` 为 Python 后端，`frontend/` 为网页，`deploy/` 为部署工具。以下命令均从项目根目录执行；不要进入 `backend/` 后直接运行脚本。原来的 `python agent.py`、`python account_admin.py`、`python task_metrics.py` 和 `uvicorn api:app` 仍由根目录兼容入口支持。`.env`、`.venv/`、`模板/`、`data/` 的位置不变，已有用户无需迁移数据。

当前实现提供终端、登录页、五个工作页面和 HTTP 后端。用户素材、模板、历史和生成文件持久保存在 `data/`，关闭程序不会删除它们。首次使用会创建空白素材库，不会自动使用仓库里的示例或个人经历。

## 模板库

网页「模板库」提供系统模板和「我的模板」。先预览，点击「使用此模板」，工作台会显示当前选择；后续任务提交时固定此选择，任务开始时复制源文件供模型读取。选择只影响后续任务，已有简历保持不变。

上传 PDF、PNG、JPG 或 WebP（单文件不超过 15 MB；PDF 不超过 10 页），填写名称并点击「上传并转换」。后端读取页面图片和文字，调用配置的视觉模型重建 LaTeX，最多进行三次转换/编译修复，编译两遍并确认预览为一页，再让模型查看截图检查重叠、裁切与对齐，通过后保存到个人模板库。转换失败可以重试，未完成的模板不能选择。可下载 LaTeX、示例 PDF 和原稿。PDF 通常无法还原原始 LaTeX，转换是对版式的重建，复杂布局可能有差异，使用前应检查预览。

首次生成完整 LaTeX，后续编译或截图检查发现问题时，只请求局部代码替换；后端核对源码版本、唯一匹配和编辑区域，全部有效才应用。匹配失败不会部分改写文件，也不会退回整份重写，而是将原因返回模型重新定位。修改后仍重新编译、检查页数与截图。页面会显示「正在局部修复模板代码」，任务日志记录应用/拒绝结果及修改数量。已有模板后续直接复用，不重复转换原稿。

模板转换独立于个人简历导入：不读取或改写个人素材、不将模板示例保存为简历版本；模型被要求替换参考人物的信息，示例内容不能作为生成简历的事实依据。个人模板和原稿均需当前用户凭据访问。

扩充系统模板时，在根目录 `模板/` 放入独立可编译的 `.tex` 文件，以及同名 `.pdf` 供预览；可选同名 `.json` 配置展示名称、简介和岗位分类，例如 `{"name":"简洁双栏","description":"适合突出项目成果的双栏版式","categories":["engineering","product"]}`。分类可多选：`engineering` 技术研发、`product` 产品运营、`design` 设计创意、`marketing` 市场销售、`business` 综合职能。现有中英文模板按示例内容默认归入技术研发；其他模板缺少分类时显示“未分类”，仅在“全部”岗位下展示。模板应支持缺图编译，使用 `geometry` 和 `graphicx`，为 `photo.jpg` 留出照片位置。登录后列表动态发现；访客示例目前仍是前端内置的两份模板，扩充访客示例时需同步其展示数据。只有 `.tex` 时仍可选择，但没有预览。新增模板后同步维护 `AGENTS.md` 的目录清单。

## 安装与配置

使用 Python 3.10 或更高版本。建议创建独立虚拟环境：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

如果系统缺少 venv 支持，可以安装系统的 `python3-venv`，或者用已安装的 uv：

```bash
uv venv --python python3 .venv
uv pip install --python .venv/bin/python -r requirements.txt
```

参考 `.env.example` 在 `.env` 中配置 `AGENT_API_KEY`、`AGENT_MODEL`，以及需要时的 `AGENT_BASE_URL`。已有 `.env` 不要覆盖。使用 `RESUME_DATA_DIR` 可指定持久数据目录。

`AGENT_REASONING_EFFORT=medium` 会在每次模型请求中显式传入 `reasoning_effort="medium"`。不支持该参数的模型应将此项留空。修改 `.env` 后重启终端或后端进程生效；同名的进程环境变量优先于 `.env`。

每次模型请求直接使用完整素材。聊天及简历生成的每次模型请求都直接携带当前用户最新的完整 `项目经历库.md`，使用 `tools.py` 直接提供文件读写、编译和预览工具。无需修改 `.env`。生成时优先覆盖已确认的经历和关键成果，确实超过一页再压缩；完整输入不等于取消一页限制，也不会使待确认事项自动成为已确认事实。

PDF 编译还需要 xelatex、fandol 中文字体、fontawesome5 与 tex-gyre。截图预览需要 `pdftoppm`（Ubuntu/Debian 的 `poppler-utils` 包）。模型和中转接口必须支持 Chat Completions 的图片输入。API 可以在未配置模型时启动，但发送消息会得到明确的配置错误。

## 简历的局部迭代

生成简历时，模型先用 `write_file` 写出第一版 LaTeX；后续默认在同一文件上用 `edit_file` 局部修改正文、加粗或排版代码；调整较大时，也允许用 `write_file` 写回修改后的完整源码，由模型自行选择。模型通过 `read_file` 获取当前内容及版本，按原代码/新代码提出局部替换。修改失败保留当前文件，成功后重新编译和检查截图；行距、下边距继续使用 `compile_pdf` 参数调整。新任务仍保存独立简历版本，已生成的历史版本不被覆盖。

## 终端

```bash
.venv/bin/python -m backend.agent
.venv/bin/python -m backend.agent --new-session
.venv/bin/python -m backend.agent --session 已有会话编号
```

默认恢复同一终端用户的最近会话；新会话仍共享该用户的素材库。启动时显示素材库路径，可以通过对话补充真实经历，也可以在没有任务运行时编辑该 Markdown。已有素材可人工复制到该用户的 `项目经历库.md`，不要把示例人物混入个人素材。

输入 `exit` 或 `quit` 退出。终端凭据保存在数据目录的 `cli-profile.json`，不要分享或提交到版本库。

## 启动后端

```bash
.venv/bin/python -m uvicorn backend.api:app --host 127.0.0.1 --port 8000
```

浏览器访问 <http://127.0.0.1:8000> 即可使用网页。若要继续使用原型时的地址，把端口改为 `8765` 并访问 <http://127.0.0.1:8765>。不要再用 `python -m http.server`，静态文件服务无法调用模型。

当前要求单进程运行，不使用多个 workers。终端和 API 不能同时占用同一个数据目录；需要分别运行时，先退出另一个入口，或指定不同的数据目录。

## 网页上传与自动入库

网页首次打开进入登录页，任何人都可注册普通账号。登录后访问自己的素材、模板、照片和简历。旧浏览器存在原工作空间凭据时，注册页默认勾选绑定原资料，沿用原用户编号和数据。模型密钥只由后端读取 `.env`，不会下发浏览器。

1. 在对话框选择 PDF、DOCX、PNG/JPEG/WebP 图片或 TXT/MD，也支持粘贴和拖入图片；输入说明后一起点击发送。前端只上传原文件，不提取文字。
2. 服务器保存原文件并提取 PDF/Word 内容；PDF 全部页面、用户图片和 Word 可转换的内嵌图片作为图片输入传给模型，扫描 PDF 同样可读。文字说明和附件进入同一轮 Agent 对话。
3. 模型识别为用户本人简历时主动整理已确认信息入库；JD、参考图与他人简历不当作用户经历。用户可明确要求只查看不保存。
4. 素材库自动读取后端结果，保留手工编辑、revision 冲突检查和用户任务锁。解析失败、模型失败可重试，刷新可恢复任务与已发送附件。
5. 原文件保存于 `data/users/<用户>/workspace/uploads/<编号>/`，经身份与会话校验才能下载。历史保存附件编号，图片只在服务器构造模型请求时编码。

每条消息最多 3 份文件，每份 15 MB；单 PDF 最多 10 页，单文件文本 6 万字符，一条消息合计不超过 12 万字符或 12 张图片/页面。旧 `.doc` 请转 DOCX；有密码的 PDF 先解密。后端需 `python-multipart`、`python-docx`、Pillow、pypdf 和 pdftoppm；Python 依赖通过 requirements.txt 安装。

旧 `/imports` 文本接口保留以兼容历史任务，但网页已不再调用。

2026-10-04 上传迁移验证：29 项自动测试通过。真实中转模型能同时读取图片中的测试编号和 DOCX 中的项目数据，并遵守“只查看不写素材”的要求；另一次真实调用完成 DOCX 个人信息与项目经历入库。浏览器验证了原文件与文字同条发送、附件历史刷新恢复和原图预览。原始附件通过字节对比确认完整保存，跨用户/会话访问被拒绝，失败任务可用原附件重试。

## 账号、邮箱验证与密码登录

用户名为 3～32 位，以英文字母开头，支持数字、点、下划线和短横线；密码为 6～128 个字符。注册账号默认都是普通用户，不会因为最先注册获得管理员权限。账号页支持修改密码和退出登录；管理员可查看用户、停用/恢复账号、重置密码。修改或重置密码、停用账号都会撤销旧登录会话。

先在网页注册自己的账号，再在服务器终端授权管理员：

```bash
.venv/bin/python -m backend.account_admin promote 你的用户名
```

使用自定义数据目录时增加 `--data-dir /你的持久数据目录`。忘记密码时，服务器管理员可运行以下命令，按提示输入新密码（不在命令参数中传密码）：

```bash
.venv/bin/python -m backend.account_admin reset-password 你的用户名
```

登录窗口提供手机登录、邮箱登录、注册账号三个入口，默认使用手机号和短信验证码，首次验证通过自动创建无密码账号，无需单独注册。旧账号通过 `/password-login.html` 登录后绑定手机号，可继续访问原资料。注册入口支持设置用户名、密码，并选择手机或邮箱验证；邮箱注册，需要用户名、邮箱、密码和邮件中的 6 位验证码。邮箱地址不限制 QQ、163、Gmail、Outlook 或企业邮箱等服务商；当前支持常见 ASCII 邮箱地址，收信是否成功取决于发件服务与收件方。注册完成后可用用户名或邮箱加密码登录；历史无邮箱账号仍可用原用户名登录，不会自动绑定或合并其他账号。暂不提供邮箱验证码登录、邮箱绑定/更换或邮箱找回密码，忘记密码由管理员协助重置。同时支持手机验证码注册、登录，以及已有账号绑定手机号；默认手机登录不需要用户名和密码；兼容的显式注册接口仍可设置两者。手机号不会自动合并到其他账号，短信找回密码暂不提供。

### 配置验证码发信

网站只需配置一个支持 TLS 的 SMTP 发件服务，用户无须开通服务。后端读取 `.env` 或部署环境中的以下变量，配置后重启：

```dotenv
RESUME_SMTP_HOST=smtp.example.com
RESUME_SMTP_PORT=465
RESUME_SMTP_SECURITY=ssl
RESUME_SMTP_USERNAME=your-smtp-user
RESUME_SMTP_PASSWORD=your-smtp-authorization-code
RESUME_EMAIL_FROM=no-reply@your-domain.example
```

也支持 `starttls` 配合服务商指定端口（通常 587），不支持明文 SMTP。发件地址需获得服务商授权；按服务商要求完成发件域名验证。密码或授权码只存服务器环境中，不写入仓库。`.env.example` 提供空配置。无需额外安装邮件 SDK。

邮件未配置时 `/auth/config` 返回 `email_enabled=false`，邮箱注册不可用；若短信已配置，仍可手机注册。两者均不可用时 `registration_open=false`，已有账号密码登录不受影响。`POST /auth/email/send` 接收 `{email}`，返回发送状态、60 秒重发间隔和 300 秒有效期，不回显验证码。`POST /auth/register` 必须提交 `{username,email,password,code}`，可保留 `legacy_token` 绑定旧工作空间。

验证码仅存带服务端密钥的摘要；有效期 5 分钟，最多 5 次错误尝试，成功创建账号时在同一事务中消费，发送失败会废弃对应验证码。发送按邮箱限制每分钟 1 次、每小时 5 次，全站每小时 100 次，并有 IP 限流。新验证码替换旧验证码。`auth-secret` 必须随数据备份。

本地验证使用 `tests/guest_ui_server.py` 的模拟发信器；其中 `/test/email-code` 仅存在于临时目录、回环地址上的测试服务，不属于生产 API。真实投递需配置发信服务后另行验证。

登录态使用 7 天有效的 HttpOnly / SameSite=Lax Cookie；数据库只保存登录凭据摘要，密码使用 Argon2id 哈希。公开部署使用 HTTPS，并设置 `RESUME_PUBLIC_ORIGIN=https://你的域名`、`RESUME_COOKIE_SECURE=true`。浏览器本地仅保留用户编号、会话位置和按用户隔离的未保存草稿；旧凭据只用于一次性绑定，绑定成功后服务端作废旧凭据。不要在绑定旧资料前清除原浏览器站点数据。

### 配置阿里云手机验证码

使用**号码认证服务 Dypnsapi** 的 `SendSmsVerifyCode` 和 `CheckSmsVerifyCode`，不是旧的普通短信 `Dysmsapi`。安装 `requirements-sms.txt`（Docker 已包含），在后端环境文件配置：

```dotenv
RESUME_SMS_PROVIDER=aliyun-pnvs
ALIBABA_CLOUD_ACCESS_KEY_ID=your-ram-access-key-id
ALIBABA_CLOUD_ACCESS_KEY_SECRET=your-ram-access-key-secret
RESUME_SMS_SIGN_NAME=恒创联众
RESUME_SMS_TEMPLATE_CODE=100001
```

签名和模板必须是当前号码认证控制台提供的配套资源。RAM 用户只需 `dypns:SendSmsVerifyCode` 与 `dypns:CheckSmsVerifyCode` 权限。密钥仅在服务器保存，不回传到浏览器。修改环境后重启本地服务；Docker 部署需重建应用容器加载环境。

配置和 SDK 齐全时 `sms_enabled=true`，这只代表本地准备就绪，不代表远端权限、额度、短信送达已验证。短信仅支持中国大陆 +86 号码，阿里云生成 6 位数字验证码，5 分钟有效；后端仅在 `Model.VerifyResult=PASS` 时接受。发送限制：同号码每分钟 1 次、每小时 5 次，全站每小时 100 次，以及 IP 限流。

发送接口返回一次性 challenge，浏览器提交验证码时同时带回。SQLite 的 `sms_attempts` 将校验绑定至手机号、用途和绑定账号，每个 challenge 最多尝试 5 次；成功后不可重复使用。重发会废弃本网站之前的 challenge。已有账号从「账号与安全」绑定手机号，之后短信登录仍访问原账号的素材与简历；未注册手机号验证通过后自动创建账号，后续登录复用同一账号。

接口：`POST /auth/sms/send`（phone、purpose=register/login/bind）；`POST /auth/sms/login`（phone、code、challenge、mode，注册时还需 username/password）；`PUT /auth/phone`（phone、code、challenge，必须已登录且有 CSRF）。短信首次自动创建账号和兼容的显式注册都支持 legacy_token 绑定原工作空间。

隔离测试：`test_sms_auth.py`、`tests/guest_ui_server.py` + `tests/browser_sms_auth.cjs` 使用模拟短信，不向真实用户发信。测试服务 `/test/sms-code` 与 `/test/sms-reset` 仅存在于临时回环服务，生产 API 没有这些入口。

## 请求示例

健康检查：`curl http://127.0.0.1:8000/health`。正常业务接口使用登录 Cookie，旧 `POST /users` 和 Bearer 凭据不再对外提供账号访问能力。只有隔离回归测试显式开启旧接口兼容。

登录后的网页控制台可运行以下示例创建会话；浏览器自动携带 HttpOnly Cookie，无需复制登录凭据：

```javascript
const auth = await fetch('/auth/me').then(r => r.json());
const session = await fetch('/sessions', {
  method: 'POST',
  headers: {
    'X-Resume-Client': 'browser',
    'X-CSRF-Token': auth.csrf,
    'X-Resume-Account': auth.account.user_id
  }
}).then(r => r.json());
console.log(session);
```

所有写请求需要 `X-Resume-Client: browser`，已登录的写请求还需 `/auth/me` 返回的 CSRF 值，跨来源写请求会被拒绝。网页额外发送 `X-Resume-Account` 防止多个标签页切换账号后误把旧草稿写入另一账号。会话创建后使用 `/sessions/{session_id}/messages` 发送/读取消息，`/sessions/{session_id}/tasks/{task_id}` 查询任务，`/sessions/{session_id}/files/{file_id}` 下载文件。

发送消息返回任务编号，不会等待模型完成。查询任务直到 `completed` 或 `failed`；`files` 列表包含文件编号与名称，按对应扩展名下载。编译失败可能只保留 .tex，不能将任务完成等同于 PDF 一定生成。

同一用户的素材被多个会话共享，因此有未完成任务时再次发送消息返回 409。换用另一个用户的凭据访问会话、任务或文件会返回 404。

## 数据迁移和备份

在「简历版本」选择一份简历，点击预览右上角「删除」并确认，可删除该版本。后端同时删除对应 PDF、同名源文件与下载记录，素材库和原始附件保留；已删除版本无法通过旧下载链接访问。

停止写入后备份整个 `data/`（或自定义数据目录），其中包括 SQLite 数据库、用户文件、`auth-secret` 验证码校验密钥以及需要继续使用的终端凭据。只备份 PDF 无法恢复会话、素材及文件归属。

```bash
docker compose -f compose.ip.yaml --env-file deploy/ip.env ps
docker compose -f compose.ip.yaml --env-file deploy/ip.env logs --tail 100 app
docker compose -f compose.ip.yaml --env-file deploy/ip.env up -d --wait
```

切回私下测试时，等待任务结束，用 `compose.ssh.yaml` 和 `deploy/ssh.env` 执行 `up -d --wait`，并移除云安全组公网端口规则。切换域名 HTTPS 时使用 `compose.yaml` 和 `deploy/deployment.env`，保持相同数据路径，并移除临时端口放行规则。上述模式只运行一个 app 实例。

### 公网 IP HTTPS（无需域名）

使用 `compose.ip-https.yaml` 和 `deploy/Caddyfile.ip`，由 Caddy 2.11.6 申请 Let's Encrypt 的 `shortlived` 公网 IP 证书并自动续期。Caddy 配置通过 `default_sni` 兼容直接输入 IP、TLS 握手不发送 SNI 的浏览器，避免 Docker NAT 后选不到公网 IP 证书。公网 TCP 80、443 必须保持可达；证书仅约 6 天有效，代理必须持续运行并保留 `resume_caddy_data` 卷，不能手动删除证书卷或依赖一次性签发。

复制 `deploy/ip-https.env.example` 为 `deploy/ip-https.env`，设置 `RESUME_PUBLIC_IP`（纯公网 IPv4）、原有镜像和数据路径。`RESUME_PROXY_IMAGE` 可使用示例中的固定 digest；若离线导入镜像，使用核对过镜像版本的本地标签。模型密钥继续从原 `deploy/app.env` 读取。等待任务结束后切换：

```bash
docker compose -f compose.ip-https.yaml --env-file deploy/ip-https.env config --quiet
docker compose -f compose.ip-https.yaml --env-file deploy/ip-https.env up -d --wait
docker compose -f compose.ip-https.yaml --env-file deploy/ip-https.env logs --tail 60 proxy
```

应用端口不再发布，只有代理监听 80、443。HTTP 自动重定向到 `https://服务器公网IP`，应用来源和 Secure Cookie 强制切换为 HTTPS。相同项目和 app 服务会被替换，原 SQLite 与文件目录继续保留。此模式替代之前 HTTP 模式，后续升级、重启、日志命令都使用此 HTTPS 配置。

必须从外网验证证书及页面，不要只看容器健康状态；申请尚未成功时 TLS 可能报错，不能用 `curl -k` 或浏览器忽略证书错误当作通过：

```bash
curl -I http://服务器公网IP
curl --fail https://服务器公网IP/health
```

确认 HTTP 跳转 HTTPS、证书链与 IP 校验通过，以及登录页可访问。切回 HTTP 时需先停止 proxy 释放 80 端口，再用 `compose.ip.yaml` 启动，保留证书卷；不要使用 `down -v`。HTTPS 负责传输加密，不替代应用限流、用量控制和编译隔离。

参考：[Let's Encrypt 公网 IP 证书](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability)、[Caddy ACME 配置](https://caddyserver.com/docs/caddyfile/directives/tls)。

### 服务器首次启动

服务器安装 Docker Engine、Compose 2.30+ 和 Python 3，准备域名并将其 A/AAAA 记录指向服务器，允许 HTTP/HTTPS 的 80、443 端口。应用端口不对公网发布，`proxy` 服务转发请求并自动管理 HTTPS。仅信任此 Compose 私有网络中的反向代理，不要另行公开应用的 8000 端口。

把部署压缩包上传服务器，解压到例如 `/opt/resume`，以下命令在该目录执行。先复制示例配置：

```bash
cp deploy/deployment.env.example deploy/deployment.env
cp .env.example deploy/app.env
chmod 600 deploy/deployment.env deploy/app.env
```

修改 `deploy/deployment.env`：

- `RESUME_IMAGE`：刚发布的完整版本标签，或仓库返回的不可变镜像 digest。
- `RESUME_DOMAIN`：实际域名，例如 resume.example.com，不带 https:// 或路径。
- `RESUME_DATA_PATH`：绝对持久目录，例如 `/srv/resume/data`；以后更新继续使用此目录。

- CPU、内存限制按实际机器容量调整；这是整台应用容器的上限，不是每个编译任务的上限。

在 `deploy/app.env` 配置模型服务和可选短信服务。Compose 使用 raw 格式读取该文件，值不写引号，`$` 等字符按字面值传入。Compose 强制将容器的数据路径设为 `/data`，来源设为 `https://RESUME_DOMAIN`，并启用 Secure Cookie，不采用 app.env 中对应的本地开发值。

```bash

sudo install -d -m 700 /srv/resume/backups

docker compose --env-file deploy/deployment.env pull
docker compose --env-file deploy/deployment.env up -d --wait
```


### 更新应用与备份

本地发布新版本镜像后，服务器修改 `deploy/deployment.env` 中的 `RESUME_IMAGE`，**保持 `RESUME_DATA_PATH` 原值**。先拉取镜像，不影响运行中的服务：

```bash
docker compose --env-file deploy/deployment.env pull app
```

选择维护时段，暂停新请求、等待已有任务结束，然后停止 app、备份并启动新版本。当前不会自动排空任务，停止服务会中断未完成任务：

```bash
docker compose --env-file deploy/deployment.env stop app
sudo python3 deploy/backup_data.py --data /srv/resume/data --output /srv/resume/backups
docker compose --env-file deploy/deployment.env up -d --no-deps --wait app
```

备份失败时先解决错误；如暂不升级，将 `RESUME_IMAGE` 改回原值并启动恢复服务。应用更新不需要删除数据目录，不需要重建数据库，更不能用本地空 data 覆盖服务器目录。证书状态由 Caddy 独立数据卷保存，不使用 `docker compose down -v` 作为更新步骤。定期把备份复制到另一台机器或独立存储，仅保存在同一块服务器磁盘不防磁盘损坏。

需要回滚时，先确认旧程序兼容当前数据库结构，再切回旧镜像；涉及不兼容数据迁移时，应把升级前备份恢复到**新的空目录**，修改 `RESUME_DATA_PATH` 指向恢复目录，配合旧镜像启动，保留原目录供排查。恢复旧备份会失去备份之后的新写入，不能把程序回滚等同于无损数据回滚。

查看运行状态与日志：

```bash
docker compose --env-file deploy/deployment.env ps
docker compose --env-file deploy/deployment.env logs --tail 100 app
docker compose --env-file deploy/deployment.env logs --tail 100 proxy
```

镜像更新只更换程序与依赖；SQLite 和用户文件继续来自同一持久挂载。部署机制参考 [Docker Compose 生产部署](https://docs.docker.com/compose/how-tos/production/)及[持久化存储说明](https://docs.docker.com/engine/storage/volumes/)，HTTPS 参考 [Caddy 文档](https://caddyserver.com/docs/automatic-https)。
