# 简历网页工作台

从项目根目录启动完整服务：

```bash
.venv/bin/python -m uvicorn backend.api:app --host 127.0.0.1 --port 8765
```

浏览器访问 <http://127.0.0.1:8765>。页面与接口由同一进程提供，不再使用 `http.server` 或直接双击 HTML。首次运行依赖与 `.env` 配置见 [本地运行](../docs/本地运行.md)。

## 四个入口

- **我的素材库**：文档式阅读、Markdown 编辑、导入和下载。内容来自当前用户的后端 `项目经历库.md`；编辑自动保存，刷新可恢复。冲突不覆盖，提供草稿备份与读取最新版本。旧原型中的本机草稿可通过「恢复旧草稿」导入。
- **简历版本**：读取当前用户历史生成的 PDF，支持真实预览、下载、新窗口查看和删除。预览右上角点击「删除」，确认后移除所选版本；没有剩余版本时清空预览。素材库和原始上传附件保留。
- **简历工作台**：对话与附件。选择文件或粘贴图片，与文字一起点击发送。原文件上传到后端，由 Agent 结合说明处理；本人简历主动整理到素材库，参考图片/JD 按用户要求分析。

- **模板库**：浏览系统模板、上传个人 PDF/图片并由后端转换为 LaTeX，预览后选择用于后续生成。提供 LaTeX、示例 PDF 和个人原稿下载。转换任务显示进度，失败可重试；模板内容不进入个人素材库。扩充系统模板的方法见 [本地运行](../docs/本地运行.md#模板库)。

模板库在电脑和手机上均提供五种岗位筛选（技术研发、产品运营、设计创意、市场销售、综合职能），与系统／个人来源取交集。手机分类栏可横向滑动，筛选不改变已选模板。现有两份系统模板归入技术研发；其他模板未配置分类时保留在“全部”，不按名称推断分类。岗位元数据配置见上面的本地运行说明，样式位于 `template-categories.css`。

## 数据与处理

前端仅负责输入、上传、素材文档编辑与结果展示，不解析 PDF/Word 内容。后端保存原始附件，提取文档文字并将用户图片、PDF 整页截图、Word 内嵌图片发送给配置的模型。PDF.js 仅用于生成结果的显示预览；模型密钥始终在后端。

每次调用都读取最新完整素材库。原附件按用户及会话保存，历史只保存附件引用，重启后仍可下载和用于后续对话。模型按用户说明识别附件用途，个人简历主动整理已确认信息，识别不清或冲突时追问，不将岗位要求当作个人经历。

每条消息最多 3 个附件，每份 15 MB，单 PDF 最多 10 页；每份文字最多 6 万字符，合计最多 12 万字符或 12 张图片/页面。支持 PDF、DOCX、PNG/JPEG/WebP、TXT/MD；旧 DOC 需另存 DOCX。扫描 PDF 以页面图片交给模型阅读。损坏、加密、超限文件会明确报告错误。

支持自行注册、密码登录、退出及账号管理，登录 Cookie 为 HttpOnly。登录窗提供手机登录、邮箱登录、注册账号三个入口，默认使用手机号和短信验证码，首次验证通过自动创建无密码账号，之后登录原账号。`password-login.html` / `legacy-login.js` 保留旧账号密码登录及原邮箱注册流程。已有账号可在「账号与安全」绑定手机号，保留原账号资料。邮件或短信配置缺失时对应功能不可用；忘记密码请联系管理员。旧浏览器首次注册可绑定原工作空间，绑定前不要清理原站点数据。注册后可在其他设备登录同一账号访问服务器资料；未保存的素材草稿按用户保留在本机，服务器保存成功后清除草稿备份。管理员由服务器终端授权，账号页提供用户查看、停用/恢复和重置密码。配置见[本地运行](../docs/本地运行.md)。

## 前端与验证

HTML + CSS + JavaScript，登录入口为 `login.html` / `login.js`，工作页面入口为 `index.html`，交互在 `app.js`。第三方依赖本地提供，见 [THIRD_PARTY.md](THIRD_PARTY.md)。Markdown 预览使用 DOMPurify 清理，不加载文档中的外部图片。简历下载经用户凭据校验后转换为临时 Blob URL，模型密钥不参与下载。

后端验证：`.venv/bin/python -m unittest discover -s tests -v`。覆盖用户隔离、素材保存冲突、自动入库、重复导入、无效模型输出不写入、失败重试与重启持久化，以及原有 Agent/本地工具/编译测试。

生成简历时，后端会将编译后的 PDF 截图交给模型检查排版，默认最多 6 轮。工作台显示预览与视觉检查进度；需要安装 `pdftoppm`，模型中转需支持图片输入。AI 生成但未完成当前版本截图检查的 PDF 不进入版本库。用户手动编译不调用模型，执行程序验收后保存新版本，由用户在编辑器预览中检查。


首页默认展示产品介绍，点击“开始制作简历”进入工作台。访客可浏览页面及系统模板示例，操作个人资料或发送消息时弹出登录窗口；登录成功后输入保留，继续点击发送即可。系统模板访客预览位于 `assets/template-cn.png` 和 `assets/template-en.png`，更新模板版式时同步预览。`landing.css` 管理首页、访客状态与登录弹窗样式。后端仍对个人数据和所有业务写入鉴权。

手机端（宽度不超过 600px）打开根地址时，先展示首页、素材库、模板库、简历版本、工作台五个大入口。`#menu` 可直接返回入口页；已有页面链接仍直达对应功能。左上角三横线按钮打开侧边导航，支持选择页面、关闭按钮、点击遮罩或 Escape 收起，切换页面保留未发送草稿。`mobile.css` 管理布局，`mobile-nav.js` 独立处理菜单，避免菜单受主应用或 PDF 模块加载影响；电脑端继续使用原有首页和侧栏。手机导航回归检查：启动本地服务后设置 `RESUME_UI_TEST_URL` 和必要时的 `PLAYWRIGHT_MODULE`，运行 `node tests/browser_mobile_nav.cjs`；设置 `RESUME_UI_BROWSER=webkit` 可使用已安装的 WebKit 检查。


### 在线微调 LaTeX

简历版本预览栏提供「编辑 LaTeX」和「下载源码包」。源码包包含对应 `.tex` 与该版本使用的 `photo.jpg`（如有）；编辑器内可单独下载当前 `.tex` 草稿。电脑并排显示源码和 PDF，700px 以下通过按钮切换。草稿按账号和原版本保存在当前浏览器，关闭再打开可恢复；草稿未重新编译时明确标记预览为上次成功编译的 PDF。

点击「编译并保存新版本」直接调用后端 XeLaTeX，不调用模型。仍执行一页、页底留白不超过 5%、照片及现有正文质量检查；失败显示原因并保留草稿，成功后保存对应源码与 PDF 为新版本，原版保留。沿用原版照片，不替换成最近上传的照片；手动修改只作用于简历，不自动修改素材库。没有对应源码的旧 PDF 会提示无法编辑。


### 正文编辑试用版

「简历版本」→「编辑正文」默认按章节展示可编辑文字，隐藏 LaTeX 命令；支持现有中英文系统模板的标题、日期、联系方式、技能与项目要点。原有加粗会在正文中显示，修改通过字符位置写回原始源码，保留样式宏、照片与布局；输入 `%`、`&`、`_` 等会自动转义。同邮箱或网址一致的链接目标随显示文字更新。需要操作完整源码时切换「高级：LaTeX 源码」，修改可双向同步，沿用原有编译、预览和新版本保存流程。

正文草稿与源码草稿一起按账号、版本保存在当前浏览器；正文修改不会自动写入素材库。本版用于修改已有段落，暂不提供新增章节、拖拽排序或所见即所得排版。正文提取采用明确支持的命令范围，不执行宏；未知命令、复杂公式等原样保留并显示部分支持提示，可通过高级模式处理。

回归：`.venv/bin/python -m unittest discover -s tests -p 'test_resume_text.py'`；启动独立的 `tests/editor_ui_server.py` 后运行 `tests/browser_resume_text.cjs`（必要时设置 `PLAYWRIGHT_MODULE`）。合成测试包含加粗保留、特殊字符、两种模式、草稿恢复、真实 PDF 编译以及 1440/390/320px 布局。

正文编辑工具栏提供「B 加粗」：选中同一段里的文字后点击，可加粗或取消加粗，也支持 Ctrl/Cmd+B。手机端可长按选择文字后使用同一按钮。修改立即写回当前源码草稿，关闭重开、切换高级源码和编译 PDF 均保留；取消加粗使用局部字重覆盖，保留原有斜体和模板样式。未选择文字时按钮不可用。


### 对话流式输出

工作台通过带账号校验的 fetch SSE 实时接收助手正文，手机和电脑共用同一流程。模型返回文字时立即追加；切到下一轮工具处理时更新进度，最终完成后用已保存历史替换临时回复。工具参数、内部推理和模板转换的内部源码不作为流式正文输出。PDF 仍在编译、内容及截图验收完成后交付。

`task-stream.js` 解析流事件，`app.js` 管理临时消息与滚动：阅读旧消息时不会被每个文字片段拉回底部。刷新或短暂断网会重新连接同一任务，并从当前回复快照恢复，不重复提交模型任务；退出登录后中止连接。服务进程重启仍按既有规则将未完成任务标为中断，不会自动重跑。

隔离回归：运行 `tests/stream_ui_server.py` 后执行 `tests/browser_streaming.cjs`（可设置 `PLAYWRIGHT_MODULE`）。覆盖任务结束前出现正文、手机/电脑布局、刷新、断网恢复与消息去重。


### 生成时锁定模板

发送文字或附件时携带工作台显示的模板 ID，选择尚未保存时暂不可发送。后端接收任务时保存模板源码快照与校验值，排队、切换其他页面或其他设备改选不会替换本次快照；工作台显示「本次已锁定」的模板名，新生成的版本卡片也记录模板名。

模型每轮收到后端绑定的本次完整模板源码，需要重读时使用无参数 `read_selected_template`。历史工具调用中的旧路径会明确重定向到本次模板，不读取其他模板。编译与交付前核对前导区样式：允许正文编辑、规定范围内的行距/下边距调整及加载照片包，其余文档类型、字体、样式宏需与所选模板一致。不一致时要求模型修正，未通过不能交付。该检查不等于像素级版式比较，仍保留原有 PDF 截图验收。用户在消息里指定了另一个模板时，需先在模板库改选后重发。


### 对话内的处理进度

工作台不再展示独立的任务耗时面板或底部「处理完成」。用户发送后立即显示消息和助手状态；`reply-progress.js` 将真实任务事件映射成「正在思考」「正在读取素材与模板」「正在生成 PDF」「正在检查排版」等简短说明，放在同一条助手回复里。收到公开正文片段后原位置流式显示，完成后移除状态，仅保留答案；最终答案支持经过清理的 Markdown 段落、列表和加粗。

进度不是模型内部推理原文，也不展示工具参数。后台计时与诊断记录保留。网络恢复、刷新和失败重试仍使用同一任务；失败提示和重试按钮位于回复中。模板转换保留模板页的状态，手动编译使用已有编辑器提示。

验证：独立 `tests/stream_ui_server.py` + `tests/browser_reply_progress.cjs`，覆盖桌面/手机进度切换、流式答案、失败/重试/刷新、格式化和 HTML 清理；`tests/browser_streaming.cjs` 继续覆盖断线恢复。
